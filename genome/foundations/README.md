# Forma foundations

These sections own foundation purpose and intended semantics. The [registry](../registry.ts) identifies authority and review status. Values, token names, and scales are deliberately unassigned. This document is not a token file and must not be consumed as one.

## Color

Color should ultimately be semantic rather than encouraging arbitrary raw-value usage. Consumers should express the purpose of a color through approved semantic tokens once defined. Destructive treatment must remain connected to destructive intent, not personal color preference.

No palette, semantic token inventory, or values are approved here. Eventual values will use established design-token conventions; no proprietary placeholder format is introduced.

## Typography

Typography should support clear hierarchy with a restrained type scale. Review the distinction between levels in the context of the information being read.

No font family, weights, sizes, or line heights are assigned. The future Design Genome public site's font direction does not automatically define Forma's typography.

## Spacing

Spacing should use a governed scale and deliberate density. Group related information and distinguish decisions through deliberate spatial relationships.

No scale, values, or density presets are assigned. Supported spacing will resolve to the approved scale once authored.

## Radius

Radius should be restrained and purposeful rather than applying excessive rounding universally. Evaluate its role in distinguishing surfaces and controls without making rounding an end in itself.

No radius values or component mappings are assigned.
